# PocketVault — Agent Notes

Offline-first Electron + React + SQLite finance tracker. See `README.md` for user-facing docs.

## Commands

- Install: `npm install` (runs `postinstall`: `electron-builder install-app-deps` + ensures the Electron binary).
- Dev: `npm run dev` / `npm run dev:desktop` (Electron + hot reload). Renderer dev server is pinned to `127.0.0.1:4321` in `electron.vite.config.mjs`; on this machine Windows reserves the `5098-5657` range for Docker/WSL, so 5173 fails with `EACCES`.
- Build bundles: `npm run build` → `out/` (`out/renderer` is also the Capacitor `webDir`).
- Preview build: `npm run start`.
- Package desktop (Windows only): `npm run build:desktop` or `npm run build:win` (or `./build-electron.sh`) → `installers/windows/` (`PocketVault-<version>.exe` + `PocketVault-<version>.msi`).
- Mobile / Capacitor: `npm run build:mobile` (= build + `cap sync android`), `npm run dev:mobile`, `npm run cap:sync`, `npm run cap:open`, `npm run assets` (regenerates Android icons/splash from `assets/icon.png`). Full signed APK build: `./build-capacitor.sh [debug|release]` (release is the default; it generates a gitignored `release.keystore`, verifies the signature, and names the artifact `installers/android/PocketVault-<version>.apk`, or `PocketVault-<version>-debug.apk`).
- Logo / icons: `npm run icons` (`scripts/generate-icon.mjs`, uses the `sharp` devDependency) renders the "PV" monogram from Roboto Bold outlines embedded in the script (source: `assets/fonts/Roboto-Bold.ttf`, Apache-2.0) into `build/icon.png` + `build/icon.ico`, the renderer favicon, and the Android source layers (`assets/icon*`, `assets/splash*`). `npm run assets` then feeds those into `@capacitor/assets` to build the Android mipmaps/splash.
- DB/repository smoke test (run from repo root):
  `npx esbuild scripts/db-smoke.mjs --bundle --platform=node --format=cjs --external:better-sqlite3 --outfile=".pv-smoke.cjs"; node .pv-smoke.cjs`
- Per-account backup isolation smoke test (run from repo root):
  `npx esbuild scripts/backup-smoke.mjs --bundle --platform=node --format=cjs --external:better-sqlite3 --external:jszip --outfile=".pv-backup-smoke.cjs"; node .pv-backup-smoke.cjs`
- Full CRUD/validation audit (run from repo root):
  `npx esbuild scripts/audit-smoke.mjs --bundle --platform=node --format=cjs --external:better-sqlite3 --outfile=".pv-audit.cjs"; node .pv-audit.cjs`
- Capacitor (Android data layer) smoke test: `node scripts/capacitor-smoke.mjs` — bundles `src/renderer/src/lib/capacitor/api.js` with its sqlite module swapped for a better-sqlite3 shim and exercises the whole adapter (no device/emulator needed).
- All tests at once: `npm test` (runs `scripts/run-tests.mjs`: db + backup + audit + capacitor).
- Large-data stress test: `npm run test:stress` (seeds ~70k rows into a temp DB and prints query timings; not part of `npm test`).
- Unit/component tests: `npm run test:unit` (Vitest + Testing Library, jsdom); coverage with `npm run test:coverage` (100% statements/lines on shared logic + wallet UI; thresholds in `vitest.config.mjs`).
- Electron E2E: `npm run test:e2e` (builds, then Playwright launches Electron with an isolated `POCKETVAULT_USER_DATA`; includes axe accessibility checks).
- Lint: `npm run lint` (ESLint 9 flat config in `eslint.config.mjs`).
- CI: `.github/workflows/test.yml` runs lint, data/unit/coverage/stress/build/audit, Electron E2E on Xvfb, and an Android debug build. `build.yml` gates installers on lint + smoke + unit tests.

## Architecture

- **Cross-platform (Electron desktop + Capacitor Android).** One React frontend builds to both. `capacitor.config.json` sets `webDir: "out/renderer"`; the native project lives in `android/`.
- **Adapter layer:** `src/renderer/src/lib/api.js` exposes a single `api` facade (a lazy Proxy). `src/renderer/src/lib/platform.js` detects Electron (`window.api`) vs Capacitor (`Capacitor.isNativePlatform()`). Electron resolves to the preload bridge; Capacitor resolves to `src/renderer/src/lib/capacitor/api.js` (SQLite + Filesystem). **All renderer code imports `api` from `@renderer/lib/api.js` — never `window.api` directly.**
- **Shared schema/logic:** `src/shared/schema.js` holds the DDL for both platforms; `src/shared/validate.js` and `src/shared/dates.js` hold pure validation/date helpers. `src/main/db/schema.js`, `validate.js`, and `repositories/helpers.js` re-export these so desktop and mobile cannot drift.
- `src/main/db/connection.js` does **not** import Electron (testable with plain Node). Main injects `app.getPath('userData')`.
- Repositories take `db` as the first argument; keep them Electron-free.
- IPC: register handlers via `handle(channel, fn, { auth })` in `src/main/ipc/handle.js`. Responses are `{ ok, data }` / `{ ok, error }`; preload unwraps and throws on error.
- Auth session lives in the main process (`src/main/db/session.js`), keyed by `webContents.id`. Never trust a `userId` from the renderer. On mobile the Capacitor adapter keeps an in-memory session (not persisted) so startup-restore semantics match desktop.

## Gotchas / decisions

- **Vite pinned to 7** (electron-vite 5 peer range excludes Vite 8). `@vitejs/plugin-react` pinned to 5.x for the same reason.
- **Tailwind v4** via `@tailwindcss/vite` — theme lives in `src/renderer/src/assets/main.css` (`@theme`), no `tailwind.config.js`/PostCSS. Dark mode is **class-based**: `@custom-variant dark (&:where(.dark, .dark *))`. Midnight tokens: `--color-dark-bg` `#000000`, `--color-dark-surface` `#1c1c1e`, `--color-dark-surface-2` `#2c2c2e`, `--color-dark-border` `#3a3a3c`, `--color-dark-rule` `#2c2c2e`, `--color-dark-muted` `#aeaeb2`, `--color-dark-faint` `#8e8e93` (utilities `dark:bg-dark-surface`, `dark:border-dark-border`, …). No dark glass; Topbar is solid.
- **Light/dark theme**: preference (`light | dark | system`) lives in `src/renderer/src/store/themeStore.js` (persisted to `localStorage` key `pocketvault.theme`, applied to `<html>` at module load to avoid a flash). `src/renderer/src/hooks/useTheme.js` is called once in `App.jsx`, watches `matchMedia('(prefers-color-scheme: dark)')` and toggles `.dark`; manual `light`/`dark` override the OS. Settings exposes it via `src/renderer/src/components/settings/ThemeSelect.jsx` (segmented radiogroup). Conventions: main bg `dark:bg-dark-bg`, cards/modals `dark:bg-dark-surface`, inputs/nested wells `dark:bg-dark-surface-2`, primary text `dark:text-gray-100/200`, muted `dark:text-dark-muted`, faint `dark:text-dark-faint`, borders `dark:border-dark-border`, rules `dark:border-dark-rule`, accent chips/badges `dark:bg-accent-950 dark:text-accent-300`. Reports charts read `resolved` from the theme store and `src/renderer/src/lib/themeColors.js` for grid/tick/tooltip colours.
- **Form conventions** (`src/renderer/src/components/ui/`): required fields show **no asterisk** — validation is inline via `Field`'s `error` prop (`@hookform/resolvers`-free, plain `react-hook-form` rules). All password fields use `PasswordInput` (Eye/EyeOff toggle) from `ui/Input.jsx`, not `Input type="password"`. `Select` renders a custom Lucide `ChevronDown` (`appearance-none` + `pr-10` + icon at `right-3`) instead of the native arrow, so pass width classes on the wrapper via `className`.
- **Tables / row actions** (`src/renderer/src/components/ui/DataTable.jsx`): desktop (`md+`) rows use the ellipsis `RowActionsMenu` (portal dropdown so it escapes the table's overflow, **text-only** items, Delete in red); mobile renders elevated stackable cards (`bg-white dark:bg-dark-surface` sitting on a `bg-slate-50 dark:bg-dark-bg` band) with a whole-card tap-to-view (`onRowClick`) plus a text-button action footer. Pass `actions={(row) => [{ key, label, tone?: 'danger', onSelect, mobile?: false }]}`; data columns accept `mobile: false` to hide on the card view.
- **CSP** is injected by `cspPlugin()` in `electron.vite.config.mjs` **only for production builds**, so Vite's dev/React-Refresh preamble works in dev.
- **Only `better-sqlite3` is in `dependencies`** (externalized/packaged); everything else is bundled from `devDependencies` to keep the package small.
- **better-sqlite3 v13 is N-API** (prebuilds in `node_modules/better-sqlite3/prebuilds/`), ABI-stable across Electron versions; `asarUnpack` keeps `*.node` outside the asar.
- **HashRouter** (not BrowserRouter) — production loads over `file://`.
- **Money**: stored as peso numbers in SQLite (schema compatibility) but every calculation uses integer centavos (`src/shared/money.js`).
- **Added table** `savings_contributions` beyond the original spec, to support "link contributions from income".
- **Backups are per-account, encrypted and password-protected** (format v8 inside an AES-256-GCM envelope; import accepts encrypted `.pvbak` and legacy `.zip` v2/v3/v4): export contains only the signed-in user's rows + their receipts; import is refused unless the backup's username matches the signed-in user, and replaces only that user's rows (other accounts untouched). Service: `src/main/services/backup.js`; crypto: `src/shared/backupCrypto.js` (PBKDF2-SHA256 310k, 16-byte salt, 12-byte IV). v8 adds budget rollover and carries v7 reconciliation; v4 adds wallet interest fields; v3 adds `wallets` + `wallet_transfers` and `wallet_id` on rows; a v2 import (or an unknown wallet id) creates/uses that account's Cash wallet instead of dropping rows. The Capacitor adapter mirrors the same ZIP format (and the `MAX_RECEIPT_BYTES`/`MAX_BACKUP_RECEIPTS_BYTES` limits) in `src/renderer/src/lib/capacitor/api.js` - keep the two in sync when the format changes.
- **Currency**: `src/shared/currency.js` derives the full ISO 4217 list, names and symbols from `Intl`. Stored per user in `user_settings`; renderer reads it via `src/renderer/src/store/settingsStore.js`; `formatCurrency()` follows it.
- **Custom categories**: `validateCategory` accepts the built-in slugs or a custom label (pattern-validated); expense/budget forms offer a "Custom…" option.
- **Soft delete / Archive**: Income, expenses, debts, budgets, savings goals, wallets and wallet transfers carry an `is_archived` column (schema **V3** adds it to the first five; V6 adds wallets/transfers). The `remove()` API/`*:remove` channels **archive** (set `is_archived = 1`) — they never `DELETE`. Every active query (list/dashboard/reports/totals/balances) filters `is_archived = 0`; each domain also exposes `restore()` + `archived()` (`*:restore` / `*:archived`). The **Archive** page (`pages/Archive.jsx`, sidebar item) lists archived rows per category with **Restore** only. Deleting receipts is no longer tied to archiving (receipts survive; `reconcileReceipts` keeps archived references). Only **"Delete all data"** (Settings → Danger Zone) hard-deletes (`services/data.js`). Budget `upsert` un-archives on conflict. Backups include `is_archived` (preserved on import).
- **Debts (schema V4)**: re-borrow was removed. A `monthly` debt now stores `first_payment_date` (the form's "First payment date", replacing "Payment day"; `payment_day` is derived from it for legacy/back-compat). `debts.receipt_path` + `debt_payments.installment_due`/`receipt_path` add optional proofs at both the debt and per-installment level. Monthly debts render a **schedule** (`src/renderer/src/lib/installments.js`: `buildInstallments` — last row absorbs the remainder; `installmentStatus` → paid/partial/overdue/upcoming) with per-row **Pay** + **Undo**; non-monthly debts keep a free-form ledger. Receipts are included in backup/reconcile/wipe (`services/backup.js`, `services/receiptCleanup.js`, `services/data.js`). Shared `ReceiptField` (`components/ui/ReceiptField.jsx`) drives all attach controls. The Capacitor adapter mirrors the desktop debt validation in `normalizeDebtWrite` (monthly requires a first payment date, `payment_day` is derived, receipts are pattern-checked) and its `account.deleteData` removes debt + payment receipts too — keep them in sync.
- **Wallets (schema V6/V7/V8/V9/V10/V11)**: `wallets` + `wallet_transfers`; `wallet_id` is required on income, expenses, debts and debt payments and is enforced by `ensureWallet` inside each repository write (not only in IPC). Balances are **derived** (opening + income − expenses + loan proceeds − payments ± transfers) in `src/shared/wallets.js` (`computeWalletBalances`/`summarizeWallets`, integer centavos); never stored. Registration seeds **Cash** at `sort_order 0`; V6 backfills legacy users and every legacy row to Cash; delete-all re-creates Cash. The first Cash wallet is the required default: it cannot be archived and its type cannot change. Every wallet write enforces a unique `lower(trim(name)) + type`, so duplicate name/type pairs are rejected (including restores). **V7 adds optional interest fields** (`interest_enabled`, `interest_rate`, `interest_crediting`, `interest_withholding`); the UI shows an estimate only, never a ledger row. `wallets.remove` archives non-default wallets. `wallets.list` **omits `card_image`** (pickers); `summary`/`get` include it. 16 card presets live in `src/renderer/src/assets/wallets.css` (+ `WALLET_STYLE_PRESETS`/`WALLET_PROVIDERS` in shared); the Add-wallet picker also exposes the 96-entry `ACCOUNT_CATALOG` (searchable banks/e-wallets without bespoke art); every face uses the **Monogram** watermark. **Cash is charcoal/gold with a ₱ watermark and no chip; the old leather art is retired.** "Other" uses `style='custom'` with a `#rrggbb` colour and/or a PNG/JPEG/WebP data URL capped at 400k chars (renderer downscale in `lib/cardImage.js`; no filesystem/backup-file work). Backups are **format v8** (§ above). The Capacitor adapter mirrors the schema/methods and `wallets.summary`; change both together. **V8** adds savings-bucket metadata (`wallet_id`, `kind`) and `recurring_rules` for bills/subscriptions/income; posting advances `next_due` and creates exactly one expense/income row. **V10 adds reconciliation flags** (`is_cleared` on income/expenses). **V9 adds credit-card fields** (`credit_limit`, `statement_day`, `due_day`, `minimum_payment`, `apr`) plus `track_only`; a credit card's opening balance is the amount owed and its derived balance is negative. Track-only accounts are excluded from net worth and cannot be used for transfers. The Bills & Debts hub (`pages/BillsDebts.jsx`) has Debts/Bills/Calendar/Payoff tabs; the payoff projection is read-only and uses monthly payments (not APR). Backups are **format v8** (above). **V11** adds `budgets.rollover` and `net_worth_snapshots`; snapshots are derived daily and cleared by import/delete-all, so they are not in the backup. Dashboard, reports, budgets and reminders are unchanged.
- **Debt payment reminders (schema V5)**: `user_settings.reminders_enabled` + `reminder_lead_days` (default 3, max 30) drive reminders for active (non-archived, not-fully-paid) **monthly and fixed-date** debts. All schedule math is pure and lives in `src/shared/reminders.js` (`buildInstallments`/`installmentStatus`/`nextUnpaidInstallment`/`effectiveDueDate`/`buildReminderPlan`); the renderer's `lib/installments.js` just re-exports it so the UI schedule and the notifications can't drift. `src/renderer/src/lib/notifications.js` (`syncDebtReminders`/`clearDebtReminders`) builds the plan and delivers it per platform: **Electron** posts the plan to `notifications:schedule` (main service `src/main/services/reminders.js` keeps one chained timer + native `Notification`; overdue reminders de-dupe once per session via a `fired` set) and **Android** schedules `@capacitor/local-notifications` (channel `debt-reminders`, ids in the `1e9` range for safe cancel; needs `POST_NOTIFICATIONS`/`SCHEDULE_EXACT_ALARM`/`RECEIVE_BOOT_COMPLETED` in the manifest). Reminders fire at **09:00 local**: one `leadDays` before the due date (upcoming), on the due date, and one when overdue. Sync is triggered on settings load, settings change, and debt create/update/payment/archive/restore; `clearDebtReminders` runs on logout. **Limitation: desktop reminders only fire while the app is running; Android fires even when closed.** The native plugin bridge still needs a device/emulator to verify.
- **Mobile shell**: phones/tablets use a fixed bottom bar (Home, Wallet, center quick-add, Reports, More) with `env(safe-area-inset-bottom)`; the hamburger/`MobileDrawer` is gone. `More` (`pages/More.jsx`) groups Money / Data / System. The quick-add sheet navigates with `?new=1` (or `?new=wallet|transfer`); Income/Expenses/Debts/Wallet consume and clear that query before opening their form. Desktop (`lg+`) keeps the sidebar and hides the bottom bar; the sidebar collapses to a 76px icon rail (localStorage `pocketvault.sidebarCollapsed`, Ctrl/Cmd+B). Do not add a second mobile nav. Dashboard Quick actions duplicate the same entry points (income, expense, bill, wallet); Android app shortcuts route directly into the hash router from `MainActivity` (`pocketvault://income?new=1`, `expenses`, `debts?tab=bills&new=1`, `wallet?new=wallet`), so `@capacitor/app` is not used. Bills uses a URL-derived active tab so the bill shortcut cannot be consumed by the Debts tab before the recurring form opens.
- **Wallet interest**: optional per money account (not Cash), `interest_enabled` + rate + crediting + 20% withholding; the UI shows a monthly estimate only. It never posts a transaction; auto-posting is a future phase. Credit/loan APR is a separate concept.
- **CSV import** (`pages/ImportCsv.jsx`, `shared/csv.js`): header `date,type,amount,category,wallet,notes`; preview only, wallet names resolve case-insensitively with Cash fallback, rows write through the normal income/expense APIs. 5 MB cap; no bank-specific formats or duplicate detection yet.
- **App lock (Android, schema V12)**: optional device biometric/screen-lock prompt on restore. Local plugin `android/app/.../BiometricPlugin.java` uses `BIOMETRIC_STRONG | DEVICE_CREDENTIAL`; the main process returns `{locked:true}` without a session and `auth:unlock` is called only after the native prompt succeeds. No app PIN is stored. Desktop has no equivalent native prompt and keeps "Require password on startup". **The native prompt still needs a real device/emulator check.**
- **Pre-login restore (desktop)**: `backup:restoreLogin` reads an encrypted/legacy backup on the login page; an existing username requires its password, a missing account is created with the chosen password, then the backup is applied and the session starts. Android restore remains post-login via Settings.
- **Version lives only in `package.json`** (+ `package-lock.json`). The renderer reads the injected `__APP_VERSION__` (see `electron.vite.config.mjs`), and `android/app/build.gradle` derives `versionCode`/`versionName` from it. Do **not** bump it on ordinary changes; release work bumps it, adds a `CHANGELOG.md` entry, and tags `vX.Y.Z`. Current base: `1.1.4` (mobile shell, wallet interest, Cash Monogram, visible Android status bar, audit fixes); previous releases: `1.1.3` (monogram cards, grouped nav, fullscreen Android shell, wallet guards), `1.1.2` (audit fixes), `1.1.1` (test/CI + accessibility fixes), `1.1.0` (wallets), `1.0.0`.
- **Toasts** use `sonner`; `<Toaster richColors position="bottom-right" />` is mounted at the App root (so toasts survive redirects/logout). Call `toast(message, variant, options?)` from `src/renderer/src/store/uiStore.js`.
- **Dashboard period filter**: `src/renderer/src/components/ui/PeriodFilter.jsx` offers By month / Custom range / All records. Every period also resolves to a **budget month** (budgets are inherently monthly): month mode = that month, range = month containing the range's `to` date, all = current month; the UI labels this ("Budgets are monthly — showing …"). Repo: `dashboardRepo.getSummary(db, userId, period)` accepts a month string or `{ from, to, month }`.
- **`monthlyTotals(db, userId, period)`** accepts a year (always 12 buckets) or `{ from, to }` (contiguous buckets only across months that actually have data; labels switch to "MMM yy" when spanning years).
- Renderer bundle is large (~2.5 MB) because jsPDF/html2canvas and Recharts are eager; code-split `src/renderer/src/lib/export.js` if needed.
- `@electron/rebuild` is a devDependency for an explicit `npm run rebuild`; electron-builder already rebuilds native deps, so its warning is informational.
- **Capacitor packages live in `devDependencies`** (they are bundled into the Android web build and are irrelevant to the Electron package, keeping `dependencies` = `better-sqlite3` only). The Capacitor SQLite layer applies migrations with idempotent statements so re-running is safe; it mirrors `src/main/db/repositories/*` SQL, so **change both** when altering data behavior.
- **Mobile-specific limits:** `files.openReceipt` (system viewer) is unsupported on Android. Receipt upload uses a hidden `<input type="file">` + Filesystem write. Mobile **backups now match the desktop ZIP format** (`manifest.json` + `account.json` + `data.json` + `receipts/`) and are wrapped in the same encrypted `.pvbak` envelope so they move freely between desktop and Android: export builds the ZIP in the renderer with `jszip`, encrypts it with the backup password, writes it to `Directory.Cache`, then opens the Android share sheet via `@capacitor/share` (no storage permission needed - `Directory.Documents` is permission-gated and unwritable on Android 10 without a legacy flag); import uses a hidden `<input type="file">` picker, decrypts `.pvbak` (or accepts a legacy ZIP), enforces the same account lock, and replaces only that user's rows. Receipts/etc. live in `Directory.Data`. CSV/PDF `saveExport` still writes to `Directory.Data`. The plugin bridge (share sheet, file picker) still needs a device/emulator to verify.
- **Android build requirements (verified on this machine):** Capacitor 8 compiles against **Java 21** and **compileSdk 36**. `android/app/capacitor.build.gradle` sets Java 21, and `android/settings.gradle` registers the **Foojay toolchain resolver** so Gradle auto-provisions a JDK 21 into `~/.gradle/jdks` when needed. `build-capacitor.sh` exports `ANDROID_HOME` (`%LOCALAPPDATA%\Android\Sdk`) and picks a JDK 21 (Gradle cache → `C:\Program Files\Java\jdk-21*` → Android Studio's `jbr`) for `JAVA_HOME`. Gradle installs missing SDK platform/build-tools automatically. **Do not run Gradle on Android Studio's JDK 25** — Groovy build-script compilation fails with "Unsupported class file major version 69"; use a JDK 21. Running Gradle with a daemon keeps a background process alive after the script exits (harmless).
- **Release APK is signed:** `android/app/build.gradle` has a `signingConfigs.release` (reads `keystore.properties` at the repo root if present, else `release.keystore` with alias/password `release`/`android`). `release.keystore` is **gitignored** — keep it safe, since Android needs the same key to update an installed app. `assembleDebug` is signed with the debug key.
- The Capacitor adapter is validated by `scripts/capacitor-smoke.mjs` (SQL logic, auth, debts math, budgets, savings, reports, account wipe) against a real SQLite engine; the native plugin bridge, Filesystem permissions and the file picker still require an emulator/device to verify.
- `android/` and `assets/` are committed; `android/`'s own `.gitignore` excludes build outputs and the copied web assets (`app/src/main/assets/public`).
